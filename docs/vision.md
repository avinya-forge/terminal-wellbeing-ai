# Vision: Terminal Wellbeing AI

## Core Purpose
To provide accessible, low-barrier mental health support through a familiar, low-stress terminal interface, leveraging AI to offer empathetic, non-judgmental conversation.

## Ideal State
A self-healing, offline-first, empathetic AI companion that respects user privacy through local-first processing and provides immediate, non-judgmental support in a low-bandwidth, high-accessibility terminal interface.

## Pipeline Laws
1. **Latest Stable Environment Only:** We do not support legacy node versions or browsers. We build for the modern web.
2. **Strict Typing:** TypeScript strict mode is non-negotiable. No `any` without explicit, documented justification.
3. **No Magic Strings:** All constants, configuration, and text literals must be centralized.
4. **Zero Architectural Drift:** Documentation (Vision, Backlog) must exactly match implementation state.

## Values
- **Data Sovereignty:** Local-first processing. User data (memories, journals) is encrypted and never leaves the device without explicit consent.
- **Universal Access:** Full WCAG 2.2 AA compliance. Screen reader optimization and keyboard-first navigation are prioritized.
- **Sustainable Intelligence:** Optimized for low power consumption and bandwidth. Models are quantized and cached efficiently.
- **Empathy:** AI responses are tuned for supportive, non-clinical engagement.
- **Safety:** Immediate redirection for crisis situations (988).

## Future Roadmap
- **Resilience:** Circuit breakers and offline robustness.
- **Personalization:** Long-term memory and deeper profile integration.
- **Accessibility:** Full WCAG AA compliance and screen reader optimization.
